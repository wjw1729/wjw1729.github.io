# 核心思想及方法
## 推理相关
![](/images/dflash/system.png)

DFlash 的系统设计见图 2。本节说明，为什么一个很小、很快的草稿模型仍能拿到很长的接受长度。

### 1. 来自目标模型的上下文特征。
先前工作（如 An et al., 2025）直接把小型扩散模型当作投机草稿模型，接受长度差，加速也很有限。为验证这一点，作者训练了一个五层的块扩散草稿模型，完全不使用目标模型的条件信息，并在若干数学基准上评估。如表 10 所示，加速通常只有大约 2–3 倍。原因是缺少足够丰富的上下文引导：草稿模型看不到目标模型的内部表示，只能几乎从零开始预测未来 token。

相比之下，大型自回归目标模型的隐表示所含信息远多于 token 级 logits。这些特征捕捉长程依赖和任务相关语义，并且隐式编码了关于未来 token 预测的信息（Samragh et al., 2025 也观察到这一点）。在 DFlash 中，给定输入 prompt，目标模型先做一次标准 prefill，生成第一个 token。这一遍里，从浅层到深层均匀抽取一组固定层的隐表示。这些隐状态被拼接后，送入一个轻量投影层，把跨层信息融合成紧凑的目标上下文特征，再用它来条件化草稿模型。
（用hidden states 信息而非token level 信息？连续信息比离散表征更丰富）


### 2. 通过 KV 注入做条件化，使接受长度能够随深度增长。
EAGLE-3 等方法也会用目标模型的隐特征，但做法是把这些特征与草稿模型的 token embedding 融合，只作为草稿模型的输入。草稿模型越深，来自目标模型的信息就越被稀释，多加层带来的接受长度增益会递减。
DFlash 的做法不同。它把融合后的目标上下文特征当作持续存在的上下文，直接注入每一层草稿模型的 Key 和 Value 投影。投影后的特征写入草稿模型的 KV cache，并在各轮起草中复用。KV 注入的细节见附录 A.3。这样，整个草稿模型都能得到稳定、一致的条件信息，接受长度可以有效地随草稿层数增加而增长。更细的分析见下(文章第 5.5.2 节)。

DFlash 的一个优点是，接受长度会随着草稿模型深度有效增长。但更深也意味着起草开销和草稿质量之间要做权衡：层数越多，表达能力越强，接受长度越长，起草延迟也越高。因此最优层数取决于部署环境。如表 6 所示，8 层草稿模型的接受长度更长，但 5 层模型在起草开销和质量之间更平衡，整体加速比更高。

表 6. 5 层草稿模型的平均加速比最高。所有 DFlash 草稿模型都用块大小 16 训练，并从目标模型的 5 层抽取隐特征。

| 设置  | Math500 加速 / τ | HumanEval 加速 / τ | MT-Bench 加速 / τ |
| --- | -------------- | ---------------- | --------------- |
| 3 层 | 4.69× / 5.64   | 3.90× / 4.61     | 2.38× / 3.18    |
| 5 层 | 4.71× / 5.99   | 3.96× / 4.94     | 2.35× / 3.37    |
| 8 层 | 4.64× / 6.33   | 3.96× / 5.29     | 2.23× / 3.50    |

### 3. 并行扩散草稿。
DFlash 快的另一个原因是起草延迟低。自回归草稿模型要多次串行前向才能生成草稿 token 或草稿树，并行度差，GPU 利用率低。DFlash 用块级扩散过程预测下一个 token 块：块内所有被 mask 的位置在一次前向中并行解码。与自回归起草相比，这种按块并行生成显著降低起草延迟，即使草稿模型更深，硬件利用率也更高。
总的来说，DFlash 把基于扩散的并行起草，和来自目标模型的紧密条件化结合在一起，在大幅降低起草延迟的同时仍能做出高质量草稿。
图 2 的含义：从目标模型抽出的隐上下文特征被融合后，注入每一层草稿模型的 Key-Value cache，用来做条件化投机。图中还标出了目标模型解码出的 token、mask token，以及双向注意力。示例里目标模型已生成 “Diffusion is good”，草稿侧在一次前向里并行预测 `for speculative decoding`。


## 训练相关
DFlash 草稿模型的训练目标，是让块级扩散预测与一个冻结的自回归目标模型的输出对齐。它没有直接沿用标准块扩散训练（Arriola et al., 2025），而是做了几处改动，以提高训练效率、可扩展性，并让训练行为与推理时的投机解码一致。

### 1. KV注入
与推理流程一致：给定由 prompt 和 response 组成的序列，先把整段干净序列送入目标模型，抽出并融合所有 token 的隐特征，再把这些隐特征作为 Key 和 Value 投影注入草稿模型，如图 4。
![](/images/dflash/kv-inject.png)


### 2. 随机采样掩码块
标准块扩散训练里，response 被均匀切成若干块，块内随机位置被 mask，模型学习去噪这些被 mask 的 token。
DFlash 按投机解码的设定来构造块。它从 response 中随机采样锚点 token，把每个锚点当作一个块的第一个位置，其余位置全部 mask。草稿模型被训练成并行预测接下来的「块大小 − 1」个 token。这与推理时的行为直接对应：草稿模型总是以目标模型产出的一个干净 token 为条件（也就是上一轮验证得到的 bonus token）。随机化锚点位置还会让草稿模型见到更多样的目标上下文特征，提高数据效率和覆盖度。如表 13 所示，这一策略同时明显提高了接受长度和加速比。

训练时，所有块拼成一条序列，用图 4 所示的稀疏注意力掩码一起处理。同一块内的 token 彼此双向注意，也可以注意到对应注入的目标上下文特征；不同块之间不允许互相注意。这样可以用 Flex Attention（Dong et al., 2024）在一次前向和反向中高效训练多个草稿块。

图 4 的含义：蓝色是目标模型提供的、用来条件化草稿模型的上下文特征。输入由干净的 prompt token ppp 和干净的 response token rrr 组成。每个被 mask 的块里，一部分干净 response token（黄色）被随机抽作锚点，mask token mmm（绿色）标出需要并行预测的位置。白色的不可见 token 表示注意力掩码，用来保证因果一致性，并防止训练时块与块之间泄漏信息。示意序列形如：r1,⟨m⟩,⟨m⟩,⟨m⟩,  r2,⟨m⟩,⟨m⟩,⟨m⟩,  r3,⟨m⟩,⟨m⟩,⟨m⟩。


### 3. 高效上下文训练。
对 EAGLE-3 这类方法，在长上下文上训练投机草稿模型很难，因为它们的 training-time test 代价很高。DFlash 固定每条序列中被 mask 块的数量，并在每个 epoch 为每条序列随机采样锚点位置，从而把训练代价控制在有界范围内，同时仍然起到数据增强的作用。

### 4.损失加权快速收敛。
在投机解码里，各个 token 并不等价。草稿块里靠前位置一旦出错，后面的 token 全部作废，所以靠前的预测对接受长度的影响大得多。训练时用加权交叉熵来体现这种不对称，强调更早的 token 位置。

具体地，对块内位置 kkk 上的 token，使用指数衰减权重
$$
w_k​=exp(-\frac{k−1​}{\gamma}),
$$
其中 $\gamma$ 控制衰减速度。这个权重优先照顾靠前位置，加快收敛，并且比均匀加权得到更高的接受长度（图 5）。
![](/images/dflash/loss-weight.png)
### 5.共享embedding和LM head
为提高训练效率，草稿模型与目标模型共享 token embedding 层和语言模型头，并且训练时保持冻结。只更新草稿 Transformer 层。这样可训练参数更少，也促使草稿模型成为一个轻量扩散适配器，与目标模型的表示空间紧密对齐。


# DFlash2
DFlash 2 没有改并行起草这条主路径。块仍然一次前向、非因果地预测完。它补的是 DFlash「每个位置独立取 top-1」留下的两处空档：候选之间不连贯，以及块尾准确率掉下去。
## 1. 路径选择：对的 token 往往已经在 top-k 里
DFlash 每个位置单独取概率最高的那个 token。相邻位置可能互相打架，比如重复同一个词，验证时整块在第一个不一致处被截断。博客在五层 Qwen3-4B、GSM8K 上的数字是：第一个位置 top-1 命中率 85.4%，但正确 token 落在 top-16 里的比例是 99.5%。若总能从这 16 个里挑对，接受长度能从 4.27 抬到 6.79。

DFlash 2 因此保留每个位置的 top-16，只给相邻候选对打分：
$$
St​(a,b)=Ut​(b)+⟨A(a)⊙H(ht​),B(b)⟩
$$

$U_t​(b)$ 仍是 DFlash 原来的 logit。后一项是 256 维 token 码本上的低秩双线性分，再乘一个由当前位置隐状态决定的门 $H(h_t)$。所有相邻对一次并行算完，只有最后沿分数走路径是串行的，而且不碰骨干网络和 LM head。贪心走最高分后继；采样时从同一组分里抽，再用拒绝采样保住目标分布，所以输出仍然无损。

相对 DSpark 那种用串行头重写全词表分布，这便宜得多：大约 +2.0M 参数、+0.6% 轮延迟，接受长度还更高（$T=0$ 时 4.61 对 4.49）。

## 2. 两抽头动态卷积：压住块尾衰减
即使选择完美，块尾召回仍会掉（oracle 从位置 0 的 99.5% 掉到位置 6 的 87.8%）。候选列表本身在变差，选择器补不了。博客把这叫做 suffix decay。

加深度有效，但太贵：3 层、5 层、15 层在块首几乎一样，差距出在块尾；15 层把起草–验证延迟增加约 15.2%。DFlash 的注意力本来就没在干块内依赖：块内注意力占比从第 1 层约 30% 降到第 5 层约 8%，而且挤在少数头上。

DFlash 2 把这件事从注意力里拆出来。每个注意力子层和 MLP 子层的前后各加一个两抽头、动态、逐通道卷积：
$$
Conv(x)t​=kt,0​⊙xt​+kt,1​⊙xt−1​
$$
卷积核不跨块边界：块内位置 1 读锚点（上一个已验证 token），位置 0 读零填充。系数是学好的基核再加一项由当前隐状态预测的小修正，每 16 个通道共享一份修正。模块初始化成恒等，所以训练起点在数值上等于普通 DFlash。

五层模型只多约 3% 参数、0.7% 轮延迟，块尾 Recall@1 就接近 15 层 DFlash。第 4、5 层的平均块内注意力也从 9.4% 掉到 0.5%，说明局部依赖改由卷积承担，注意力回去读目标上下文。
